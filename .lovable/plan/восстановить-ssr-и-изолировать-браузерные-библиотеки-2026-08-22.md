# Восстановить SSR и изолировать браузерные библиотеки

## Что изменится
- Вернуть SSR для публичных страниц: убрать глобальный `ssr: false`, SPA-режим и временный SPA-шлюз из конфигурации сборки.
- Сохранить клиентский режим только для закрытого административного раздела, где SEO не требуется.
- Изолировать 3D-просмотр: загружать модуль с `three`, `@react-three/fiber` и `@react-three/drei` только после гидратации браузера; на сервере и до загрузки показывать стабильную заглушку того же размера.
- Изолировать PDF-движок: убрать статические связи маршрутов и компонентов с модулями генерации PDF, загружать их динамически только внутри обработчиков пользовательских действий.
- Оставить `xlsx` исключительно в серверном обработчике загрузки спецификаций; проверить, что он не попадает в React SSR-граф.

## Технические детали
- Использовать `ClientOnly` + `Suspense` для 3D-компонента, при этом сам модуль `cad-viewer.tsx` не будет статически импортирован SSR-доступным модулем.
- Перенести `import("@/lib/invoice-pdf")` и `import("@/lib/spec-pdf")` непосредственно в функции скачивания/оформления, чтобы `pdfmake` и его VFS не анализировались при импорте страниц.
- Удалить VPS-обходы, созданные для SPA/отключения SSR; не добавлять `ssr.external` и не отключать SSR для SEO-маршрутов.
- Проверить production-сборку с `DEPLOY_TARGET=vps`, наличие пререндеренных публичных страниц и отсутствие `__exportAll`-падения; затем проверить ключевые страницы в браузере.
